# 进程与资源采集

5.3.3 的默认采集器继续使用 Python 标准库、SSH 和已有会话记录。改进重点是会话归属、进程身份和资源增量，未安装 eBPF、hooks、代理或证书，也不向 CLI 注入输入。

## 对话正文与硬件分开采集

对话输出层读取明确的助手正文增量，与CPU、GPU、磁盘及TCP资源独立。模型持续输出文字时，本机硬件指标可能很低或不可观测，不能因此隐藏已确认的新正文。输出层不复用根日志的字节增长、Token计数或工具事件数；光标、计时器与输入草稿不提供活动。可见正文属于有界观测下界，滚屏、折叠和日志批量落盘会降低覆盖。详见 [声浪说明](WAVE_GUIDE.zh-CN.md)。

## 一次发现，共用进程树

每次发现进程后建立一个只读快照和父子索引，供窗格匹配与资源采样复用。采集器以进程实例而非仅 PID 建立基线：Linux 使用 `/proc/PID/stat` 的启动时钟，macOS 使用 `ps` 的进程启动时间。macOS 启动时间只有秒级精度，同一秒内极快的 PID 复用仍存在识别边界。PID 复用、重连、计数回退或采样中断时，先重建基线，不把历史累计当成新活动。

采样时再次核对父子关系；祖先进程消失、改变身份或脱离原树时，排除旧快照中的整条后代分支，降低覆盖，不把它继续计入原会话。

远端由 tmux 窗格的进程树定位 CLI；本机通过打开的 rollout 文件关联 Codex 会话。先确认同一宿主打开了多少会话，再应用关注列表或显示数量限制。隐藏某个会话不会把共享宿主变成另一个会话的独占资源。

`attribution` 表示当前来源的归属范围：`exclusive` 为仅关联到一个会话的采样进程树，`shared` 为共享宿主，`unattributed` 为不足以确认归属。它描述会话级关联，不承诺每条系统活动都属于具体某一回合。无法确认时保留边界，不把共享资源指定给“最新的会话”。

## CPU

- Linux 读取各进程的 `utime + stime`，不再叠加已回收子进程的 `cutime/cstime`。
- macOS 对选中的进程批量读取 CPU 时间与 RSS。
- 先按进程实例计算连续样本差值，再按所属进程树汇总。`100%` 表示一个逻辑核，多核计算可以超过 `100%`。
- `cpu_seconds` 是接入后连续样本中已观测到的增量总和，不是完整生命周期累计。首次、缺口、新进程或缺失数据不能冒充已知零活动。

CPU 同时用于硬件声浪、悬停与辅助功能说明。共享进程会注明共享，不能据此把其中所有对话都判为运行。

## Linux I/O

旧版本读取 `/proc/PID/io`，其中包含父进程已回收子进程的累计计数。将它与子进程增量直接相加可能重复统计。

新版在有界预算内读取 `/proc/PID/task/TID/io`，只累计已观测活跃线程的自身增量，按进程和线程启动身份验证连续性，不再把父进程回收累计加入同一账本。

| 字段 | 含义 |
| --- | --- |
| `io_scope=observed_process_tree_threads` | 已关联进程树中被采样到的活跃线程 |
| `io_kind=thread_syscall_bytes` | `rchar/wchar` 系统调用字节，包含缓存、管道与终端等，并非纯磁盘字节 |
| `io_read/write_bytes`、`io_read/write_per_second` | 连续线程样本确认的系统调用字节增量和速度，保留接口兼容，不驱动磁盘声浪 |
| `disk_read/write_bytes`、`disk_read/write_per_second` | 同一观测范围内 `read_bytes/write_bytes` 的计数增量；缓存命中不必产生物理读盘 |
| `io_lower_bound=true` | 仅表示已观测下界，不能当作完整账单 |

两次采样之间创建又退出的线程可能完全漏采；退出后的最后一段活动也未必可见。新线程首先建立基线，不把接入前数据加入；权限、预算、成员变化和不连续样本会降低覆盖。`*_complete` 描述本次采样覆盖，不能证明已捕获所有短命工作。

macOS 本次没有新增磁盘、系统调用 I/O 和 TCP 计数支持，保持未知。

## 网络与采样节奏

Linux 沿用进程 FD 与 TCP socket 身份关联，仅累计可归属的连续收发增量。共享 socket 不重复记入两个会话，缺少字段、权限或跨网络命名空间时保留未知。其他目标进程树的 FD 未完整读取时，也不能证明当前 socket 为独占：标记 `network_attribution_unknown=true`、`network_reason=ownership_unknown`，不累计这部分潜在共享流量。数据不包含请求正文、目标地址或文件路径。

CPU、磁盘和网络约每秒采样，共用 TCP 查询并限制进程、线程及 FD 数量；线程预算在目标进程树与其成员间公平分配，避免某个大任务耗尽所有名额。后台只允许一个资源工作线程。耗时资源采集不会阻塞状态流。缓存超过四秒失效，重新显示时建立新基准。

这仍是轮询采集，不能提供完整的命令执行历史或逐文件审计。后续如需要捕捉短命 exec/exit、文件操作和 TLS 请求，可以增加可选 Linux 事件后端，并对丢失、截断和无法归属的事件作明确标记。

## 脱离原进程树的 GPU 实验

Claude 发起的实验可能脱离父进程树，前台和后台任务壳都已结束，GPU子进程却继续执行。仅沿原树查找会漏掉这些实验。

对 NVIDIA 逐进程列表发现的候选，采集器读取单个白名单键 `CLAUDE_CODE_SESSION_ID`，与当前主会话日志确认的ID精确匹配，并核对同一系统用户、进程启动身份和唯一归属。已有其他关注会话的正常进程树归属优先，不重复认领。不按目录、会话名称、最近活跃时间或整机利用率猜测归属，也不遍历全机环境变量。

确认后的分支与原进程树合并为有界会话关联集合。`scope/cpu_scope/gpu_scope=session_processes`、`io_scope=observed_session_process_threads` 明确口径，`associated_process_count` / `associated_gpu_process_count` 表示补充关联进程数，不能当作智能体或任务数量。`process_activity[].association=claude_session_env` 只标识证据来源，不输出环境变量原值。

首次发现先确认归属、建立基线，等待查询前已确认进程身份的新GPU样本，不把发现过程中的旧数据转给新进程。这些进程需出现新的 GPU 计算样本或连续 CPU 活动才补充后台运行状态；仅有会话标识、显存占用或活着的进程不算工作。进程消失、PID复用、会话标识变化、过期或归属冲突时撤销旧证据。缺少保留会话标识、跨机器或驱动不支持的脱离实验仍可能无法自动确认。

## GPU 点采样

Linux 可选读取已有 `nvidia-smi pmon` 的逐进程 SM 指标。一次批量查询约每三秒进行，失败退避，过期保持未知；不安装驱动，也不读取GPU请求正文。PID启动身份再次核对后才关联到当前进程树，未关联进程与主机总利用率不分摊给会话。

`gpu_kind=process_sm_point_sample` 表示真实采样点，`gpu_aggregation=sum_process_sm_percent` 表示已关联进程／设备数值之和。这不是去重后的整张设备利用率；多个进程或GPU相加可超过100%。MIG或缺失SM字段保持未知，显存占用不会换算成利用率。

`gpu_poll_interval_seconds` 是查询周期，`gpu_interval_seconds=null` 表示驱动观测窗口未知。不能把三秒查询周期当作三秒连续计算。声浪只在新采样点绘GPU峰值，不把点值铺满两次查询之间的空白。

## 与运行状态的关系

生命周期、已确认子任务、当前输入与错误状态共同决定运行/等待。明确的前台回合完成不会被资源活动推翻；后台任务单独核对。已记录任务的输出文件与进程 stdout/stderr 设备号、inode 精确匹配后，只使用该分支及后代的连续 CPU、磁盘和新 GPU 样本作为后台进展证据。宿主总CPU、在线数和显存占用不能代替任务关联。

此前已确认后台活动，但随后资源样本缺失或过期时，显示后台状态待核实，停止沿用旧波形，不把观测缺口当作完成。初次尚未采到资源和普通保留终端不会因此全部进入待核实状态。零活动不证明任务已经完成，模型服务端思考时本机指标也可能很低。

设计参考了 [AgentSight](https://github.com/eunomia-bpf/agentsight) 的进程身份和归属证据、[Tetragon](https://github.com/cilium/tetragon) 的执行身份模型，以及 [iron-sensor](https://github.com/ironsh/iron-sensor) 的进程树结构。实现保留 Orbit 的只读轻量采样方式，未引入这些项目的运行时或复制其实现代码。
